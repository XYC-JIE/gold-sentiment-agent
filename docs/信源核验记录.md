## 2026-09-19（Task 5b：金价源 stooq → 新浪财经）

### 背景

T13 端到端联调实测，stooq 端点 `https://stooq.com/q/d/l/?s=xauusd&i=d` 已**长期失效**：本机直连返回 JS 反爬验证页，CI 侧返回 HTTP 404 "does not exist or has been moved"。两个环境都复现，不是网络抖动。后果是 `gold_close` 恒空、双轴对照图永不生成——而 T5 的单测是打桩的，**照样全绿**。

改用新浪财经现货黄金报价 `https://hq.sinajs.cn/list=hf_XAU`。

### 探测 1：带 Referer

```bash
curl -s -m 15 -H "Referer: https://finance.sina.com.cn" "https://hq.sinajs.cn/list=hf_XAU" | iconv -f gbk -t utf-8
```

实际输出（HTTP 200）：

```
var hq_str_hf_XAU="4378.29,4341.620,4378.29,4378.69,4399.49,4334.23,04:54:00,4341.62,4343.47,0,0,0,2026-09-19,伦敦金（现货黄金）";
```

响应头：

```
HTTP/1.1 200 OK
Content-Length: 131
Content-Type: application/javascript; charset=GB18030
```

### 探测 2：**不带** Referer（关键——决定 Referer 是否必需）

```bash
curl -s -m 15 "https://hq.sinajs.cn/list=hf_XAU" | head -c 200
```

实际输出：

```
Forbidden
```

响应头：

```
HTTP/1.1 403 Forbidden
Content-Length: 9
```

### 结论

| 探测 | HTTP 状态 | 响应体 | 判定 |
|---|---|---|---|
| 带 `Referer: https://finance.sina.com.cn` | 200 | `var hq_str_hf_XAU="4378.29,...,2026-09-19,伦敦金（现货黄金）";` | 可用 |
| 不带 Referer | **403 Forbidden** | `Forbidden` | 被拒 |

**Referer 是必需的头，不是可选优化。** 不带 Referer 时新浪返回 **HTTP 403 + 纯文本 `Forbidden`**（长度为 9 字节，既不是空响应也不是行情数据）。

> 注意一个容易踩的坑：真实的不带 Referer 失败形态是 **403 状态码**，`Collector.get()` 里的 `raise_for_status()` 会先抛 `requests.HTTPError`；而采集器里那句 `新浪返回格式不符` 的 `ValueError` 只在「HTTP 200 但 body 不含引号字符串」时才会触发（对应单测里打桩的 `<html>反爬页面</html>`）。两者是不同分支，联调时别把前者误判为后者。
>
> 编码：响应 `Content-Type` 声明 `charset=GB18030`（GBK 的超集）。采集器用 `resp.content.decode("gbk")` 自行解码，不依赖 requests 的编码猜测。fixture `tests/fixtures/sina_gold.txt` 亦存为 **GBK**，与线上一致。
